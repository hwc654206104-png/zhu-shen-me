# 猪什么 | AI 协作开发的微信小程序

**从冰箱里的食材出发，解决“今天吃什么”。**

“猪什么”是一款面向做饭新手和日常下厨者的微信小程序。用户记录现有食材、选择用餐人数和口味，程序生成菜单并提供菜谱步骤、收藏和做菜进度。

这是一个以真实使用问题为起点、由项目发起人与 AI 持续协作完成的项目：从需求梳理、原型设计，到小程序迁移、推荐规则、云端同步与测试，均经过多轮反馈和修正。项目发起人负责提出问题、做产品取舍、确认交互和验收；AI 协助调研、编写与审查代码、设计测试、定位问题和整理文档。

> **项目亮点：**把“调用 AI 写代码”扩展为完整的产品开发流程——明确规则、拆分任务、生成实现、验证结果，再依据真实反馈迭代。

## 为什么做这个项目

日常做饭有两个常见困难：冰箱里有食材，却不知道能做什么；找到菜谱后，又发现需要另外购买不少食材。对于新手来说，选菜、准备材料和跟着做还需要在多个页面之间切换。

项目围绕一条完整路径展开：

**管理冰箱 → 选择人数和口味 → 生成菜单 → 保留喜欢的菜并更换其他菜 → 查看做法 → 记录进度**

用户还可以通过盲盒寻找灵感、收藏单道菜，并在完成一餐后自行选择是否移除用过的食材。

## 产品功能

- **我的冰箱**：维护已有食材，通过分类归并和别名搜索降低录入复杂度。例如，五花肉、里脊肉可归入“猪肉”，参与对应菜谱匹配。
- **菜单生成**：按人数、菜数、菜系、辣度和咸淡筛选；优先利用现有食材，支持展示需要补充的食材与调料。
- **食材限制开关**：勾选“仅用冰箱食材”时，必需食材应在冰箱中；不勾选时允许推荐搭配其他食材的菜。葱、姜、蒜作为默认常备食材。
- **保留与换菜**：对喜欢的菜点击“保留”，换一份时替换其余菜；同一轮中将 A＋B 与 B＋A 识别为同一组合，避免靠交换顺序制造“新菜单”。
- **单菜收藏与做菜进度**：收藏具体菜谱；明确点击开始后才进入“正在做”，支持继续、结束和完成后按需整理冰箱。
- **菜谱盲盒**：随机发现菜谱，查看做法或收藏。
- **好友分享**：通过邀请建立关系，查看好友分享的收藏菜谱与成就。

## AI 协作开发：从想法到可验证的功能

项目并非一次生成成品，而是在反复提出问题、检查结果和修正方案的过程中形成。

1. **定义问题与产品规则**：项目发起人从实际使用出发提出需求，例如“同一种食材不必分得过细”“收藏应该按单道菜”“看一眼菜谱不代表正在做”。AI 协助将需求整理为可实现的规则和验收场景。
2. **设计和迁移界面**：先通过原型确认页面与流程，再逐步迁移到微信小程序原生组件；根据开发者工具和用户反馈修正导航、按钮、布局和文字显示。
3. **实现与审查**：AI 辅助修改小程序页面、推荐逻辑、菜谱数据处理和云函数；对涉及旧数据的调整，结合现有代码和历史决策检查兼容性。
4. **复现问题并编写回归**：当用户发现“重新生成后无菜可选”“生成菜单后冰箱食材减少”等问题时，先追踪状态与调用链，再围绕具体场景构造测试，验证修复并避免反复出现。
5. **验证与交付**：结合本地测试、微信开发者工具编译和用户真机反馈逐步迭代；区分本地源码、上传版本、体验版与正式版的状态，避免把静态检查当作真机验证。

这一过程体现的是**需求判断、任务拆解、AI 协作、代码核查和结果验收**的结合。AI 负责加速实现和验证，产品方向和关键取舍由人决定。

## 技术设计与问题解决

### 1. 食材归并与一对多匹配

冰箱录入面向普通用户，菜谱数据则可能使用更细的食材名称。项目通过食材分组和别名映射，将用户录入的大类展开到相关菜谱索引，例如“猪肉”关联里脊肉、五花肉等菜谱。索引和菜谱仍保留各自标识，以支持已有数据兼容。

### 2. 菜单推荐与去重

推荐过程综合用户选择、库存匹配、缺失食材、菜品类型及历史记录。严格模式过滤缺少必需食材的菜；宽松模式允许补充食材，并保持与冰箱库存的关联。

“换一份”按无序菜谱组合记录同轮历史，避免 A＋B 与 B＋A 重复；“保留”功能将锁定菜参与整餐搭配计算，只替换未保留部分。新一轮生成可以再次使用历史菜谱，避免长期历史把候选全部耗尽。

### 3. 冰箱同步与状态保护

本地状态与云端食材同步需要处理网络失败、旧数据和并发修改。同步代码记录待处理修改和已确认版本，并在同步时根据远端状态重新合并改动。菜单生成和浏览不应扣减冰箱食材；用户可在完成一餐后自行选择要移除的食材。

### 4. 大菜谱库与小程序包体积

公开版包含 **1,676 道菜谱、599 种食材**。项目将菜谱详情放入分包，并通过构建脚本生成索引与压缩数据，使主页面能够使用索引进行匹配，再进入详情查看完整做法。

### 5. 旧数据兼容与好友共享

收藏从“整餐”调整为“单道菜”时，兼容旧收藏记录，按菜谱展示并去重。好友共享使用云函数处理邀请、关系和收藏访问；好友数据读取以用户主动建立的关系为前提。

## 测试与验证

项目在 `tests/` 中保留了针对核心规则的 Node.js 测试。以下命令可在仓库根目录执行：

```bash
node tests/menu-pantry-mode.cjs
node tests/menu-refresh-boundary.cjs
node tests/menu-lock-lifecycle.cjs
node tests/menu-generation-inventory.cjs
node tests/single-recipe-favorites.cjs
```

这些测试覆盖食材模式、菜单组合去重、保留菜品、生成菜单时的库存保护和单菜收藏等路径。开发过程中还使用微信开发者工具进行模板编译，并结合用户的真机反馈修复问题。

**验证边界：**本地自动化和模板编译不等于所有机型的真机验收；公开副本在排除部分菜谱后进行了基础测试，完整云端流程需使用自己的测试环境验证。

## 项目结构

```text
miniprogram/                 微信小程序页面、组件与本地数据
  pages/                     首页、冰箱、菜单、盲盒、好友等页面
  recipe-book/               菜谱详情分包
  utils/                     菜单选择、食材映射、同步与收藏逻辑
cloudfunctions/              微信云开发云函数
scripts/                     菜谱数据处理和构建脚本
tests/                       Node.js 测试
docs/miniapp/recipes/       公开版菜谱数据及第三方许可文件
```

## 本地运行

1. 安装 [微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)，导入本仓库目录。
2. 配置**自己的小程序 AppID**。仓库中的原项目配置仅供参考。
3. 如需使用食材同步、好友和共享功能，请创建自己的微信云开发环境，修改 `miniprogram/app.js` 中的环境 ID，按自身环境配置数据库并部署 `cloudfunctions/` 下的云函数。
4. 在模拟器或真机预览。请先在独立测试环境验证云函数权限和数据读写，不要直接覆盖现有正式环境。

## 数据与许可

公开版已重新构建菜谱与食材索引。由于公开再分发范围尚未确认，**CookLikeHOC 原文及其 40 道菜谱未包含在本仓库**，所以公开版与完整项目数据不同。

其他第三方菜谱的许可文件位于 [`docs/miniapp/recipes/references/`](docs/miniapp/recipes/references/)。使用或再分发时，请遵循对应来源的许可和署名要求。本仓库暂未为项目整体指定开源许可证。

本仓库保留运行所需的菜谱数据；部分采集脚本和测试依赖的上游原始资料未包含。菜谱数据经过程序检查，实际烹饪效果和用量仍需根据食材及个人情况判断。
